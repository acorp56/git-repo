# Павхелп: каркас MVP

Рабочая версия по прототипу `../pavhelp-prototype.html`. TypeScript везде:

| Папка | Что это |
|---|---|
| `packages/core` | Общие правила без зависимостей: допуск донора, совместимость групп крови, уровни и награды, симптом-чекер (`RED`), валидация SOS, тихие часы. Используются и сервером, и интерфейсом, поэтому проверки совпадают |
| `apps/api` | API на Fastify + PostgreSQL/PostGIS: вход (код на email, Яндекс ID, Telegram), города, банки крови, кабинет клиники, Telegram-бот, жалобы, питомцы и медкарта, SOS, подбор доноров по радиусу, рассылка волнами, отклики, поездка донора, подтверждение сдачи, чат, капли |
| `apps/web` | PWA на Next.js: экраны из прототипа |

## Запуск

Нужны Node.js 22+ и PostgreSQL 15+ с расширением PostGIS.

```bash
docker compose up -d                 # PostgreSQL + PostGIS на localhost:5432 (или свой сервер)
npm install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local
npm run seed                         # миграции и справочник клиник
npm run dev:api                      # http://localhost:4000
npm run dev:web                      # http://localhost:3000
```

Вход по email в разработке: письмо с кодом не отправляется, код пишется в лог API (`MAIL_PROVIDER=log`). В продакшене этот режим запрещён: нужен почтовый сервис (`MAIL_PROVIDER=smtp`, `SMTP_URL`), а на домене — SPF, DKIM и DMARC, иначе письма уйдут в спам.

Проверки:

```bash
npm run typecheck
npm test     # тесты core и интеграционные тесты API на базе pavhelp_test (TEST_DATABASE_URL)
```

## Как устроено

**Подбор доноров** (`apps/api/src/services/matching.ts`). SQL отбирает кандидатов по виду, группе, весу, возрасту, интервалу после сдачи и радиусу от клиники (`ST_DWithin`). Затем каждый проходит `eligibility()` из `core`: те же правила, что пользователь видит в анкете. Рассылка идёт волнами 10 → 20 → 50 км; если кровь нужна питомцу, который сам сдавал кровь («Донор Павхелпа»), — сразу 20 → 50 км. Следующая волна запускается, если донора не выбрали за 10 минут (срочно), 30 минут (сегодня) или 2 часа (плановая), сразу после «Донор не приедет» и по кнопке «Искать в 50 км». Ночью SOS получают только те, кто включил «Будить ночью»; доноры на паузе, на лечении, после переливания и «в памяти» не получают SOS. Запрос нового аккаунта (до 7 дней) до подтверждения клиникой уходит только 5 ближайшим донорам.

**Города.** 94 города России из прототипа (`packages/core/src/cities.ts`), у Москвы и Петербурга настоящие районы, у остальных — части города. Лента, клиники и банки крови — по выбранному городу; геолокация находит ближайший город и район. Демо-клиники заведены только в Петербурге и Москве.

**Банки крови.** Клиника ведёт запас в кабинете (`blood_stock`). В форме SOS, в своём запросе и в разделе «Экстренно» показываем подходящие позиции по виду, группе и компоненту (`stockMatch()` в `core`), при неизвестной группе — с пометкой «клиника проверит совместимость».

**Автозакрытие.** Через 24 часа без выбора донора хозяину приходит «Ещё ищете донора?» (в запросе, баннером на главной и в боте). Без ответа 12 часов запрос закрывается. «Да, ещё ищем» продлевает запрос и повторно уведомляет доноров.

**Кабинет клиники** (`/clinic/:id`): «Питомец у нас» ставит отметку «Клиника подтвердила», «Не у нас» скрывает запрос до проверки модератором; подтверждение сдач вне Павхелпа (капли донору); банк крови ± по дозам. Все действия пишутся в `clinic_audit`. Сотрудника добавляет администратор: `npm run clinic:staff -w @pavhelp/api -- <email> <clinicId> <admin|vet>`.

**Telegram-бот.** «Подключить Telegram» в настройках даёт deep link `t.me/<бот>?start=<token>`, бот привязывает `chat_id` к аккаунту. В SOS-сообщении кнопки «Могу помочь», «Не сейчас» и «Открыть в Павхелпе»; «Могу помочь» откликается сразу, если подходит один питомец, иначе предлагает выбрать. Webhook — `POST /telegram/webhook` с `secret_token`. Сообщения отправляются после COMMIT, чтобы медленный Telegram не держал блокировку.

**Вход.** Одноразовый код из 6 цифр на email: действует 10 минут, до 5 попыток, повторная отправка через 60 секунд, в базе только хеш кода. Адрес приводится к нижнему регистру, при опечатке в домене (`gmial.com`) интерфейс подсказывает исправление. Кто подтвердил адрес, тот и владелец аккаунта с этим адресом.

**Приватность.** Точный адрес не хранится: точка питомца — центр района со сдвигом. Телефон для связи необязателен. После выбора донора номера скрыты с обеих сторон: каждый сам нажимает «Показать мой номер», номер собеседника виден, только если он открыл свой, и его можно скрыть обратно. До этого связь через чат. Публичная страница `/r/<slug>` без личных данных. Есть выгрузка и удаление своих данных.

**Капли** считаются только на сервере, журнал `xp_events` с `UNIQUE (user_id, kind, ref)`: одно событие начисляется один раз. За сдачу — только после подтверждения хозяином («Кровь взяли»). Сдача вне Павхелпа сразу сдвигает дату готовности, но капли ждут подтверждения клиникой.

**Безопасность.** Сессия в httpOnly-cookie, в базе только хеш токена. Изменяющие запросы принимаются только с `Content-Type: application/json` (вместе с `SameSite=Lax` это защита от CSRF). Лимиты: 10 писем с кодом в час с IP, повторная отправка через 60 с, 5 попыток кода. SOS: один активный запрос на питомца (дубли ловим по питомцу или кличке), не больше 2 активных и 3 за сутки на аккаунт; лимит снимает поддержка.

**Защита от мошенников.** Отметки «Клиника подтвердила / проверяет», плашка «новый аккаунт» и стаж автора. Жалоба на запрос или собеседника (6 причин): запрос скрывается из ленты пожаловавшегося, жалоба на деньги или продажу крови закрывает чат, жалобы от 3 разных людей замораживают аккаунт и скрывают его запросы до проверки модератором. В чате закреплено «Донорство бесплатное», сообщения с просьбами о деньгах помечаются (`RISK`), номер карты (проверка по алгоритму Луна) отправить нельзя, в описании SOS запрещены слова о купле-продаже крови (`SELL`). Адрес возврата после входа проверяется `safeReturnTo()`. Подпись Telegram Login Widget проверяется по документации Telegram.

## Отличия от прототипа

- Проверка прививок строже: нужны обе (комплексная и от бешенства) не старше года. В прототипе при пустой медкарте проверка проходила.
- «Яд» в тревожных признаках ловится как отдельное слово. В прототипе `\bяд` не срабатывал на кириллице.
- Аккаунты разных способов входа не склеиваются автоматически по email или телефону: привязка — только из настроек, когда пользователь уже вошёл. Исключение — вход по коду на email: кто подтвердил адрес, тот и владелец аккаунта с этим адресом.

## Что ещё не сделано

- **Фото** у запроса и питомца (галерея до 6 фото, обложка, жалоба на фото, обязательное фото донора): нужны S3-совместимое хранилище в РФ, превью и модерация. Пока фото нет нигде.
- **Бонусы партнёров** за подтверждённые сдачи: нужны партнёры и способ выдачи промокодов.
- **Модерация.** Жалобы, замороженные аккаунты и запросы «Не у нас» складываются в базу (`reports`, `users.frozen_at`, `requests.hidden`), но экрана модератора пока нет — разбирать через базу.
- **Поддержка.** FAQ и форма есть, обращение уходит письмом. Helpdesk с ответом в Telegram и списком обращений — позже.
- **Пересылка чата SOS в Telegram** и ответы из бота обратно в чат. Сейчас бот присылает уведомление о новом сообщении со ссылкой.
- **Плановые запросы** не закрываются после даты операции: в форме нет даты. Закрываются общим автозакрытием.
- **Почтовый сервис.** Отправка через SMTP готова (`SmtpMailer`), нужно выбрать сервис (например Unisender Go или Yandex 360), подтвердить домен и прописать SPF, DKIM, DMARC.
- **Новый вход Telegram на OpenID Connect, VK ID, Сбер ID, МТС ID** из `auth/AUTH.md`. Папки `auth/` в переписке не было — пришлите её, и я перенесу. Сейчас проверяется подпись Telegram Login Widget.
- **Web Push.** Обработчик в `public/sw.js` и подсказка для iPhone есть, нужны VAPID-ключи, хранение подписок и отправка с сервера.
- **ИИ** (YandexGPT или GigaChat через свой прокси): уточняющие вопросы симптом-чекера, «SOS одной фразой», распознавание ветпаспорта. Сейчас работает запасной вариант на правилах; промпты лежат в прототипе.
- **Истории спасения**, рейтинг районов, задания недели, учёт репостов и приглашений.
- **Реалтайм.** Карточка запроса обновляется раз в 10 секунд; потом — WebSocket или SSE.
- **Свайп назад.** Навигация идёт через History API (Next.js), поэтому системный жест «назад» в Safari и Android работает. Своего жеста с «подглядыванием» предыдущего экрана, как в прототипе, нет.
- **Тексты документов** (`/legal/*`) — шаблон из прототипа: их должен проверить юрист, вписать реквизиты оператора и подать уведомление в Роскомнадзор.
- **Справочник городов и клиник.** 94 города — из прототипа; в продакшене — ФИАС/ГАР или OSM и реальные клиники каждого города.
- **IP для лимитов.** API доверяет `X-Forwarded-For` (`trustProxy`). В продакшене API должен быть доступен только через свой прокси (nginx), который перезаписывает этот заголовок, иначе лимит писем по IP можно обойти.
- **Бренд.** Надпись «пав•хелп» и иконка сделаны по описанию из README; финальные векторные версии — от дизайнера. Товарный знак, домен pavhelp.ru и имя бота нужно проверить до запуска.
