# Кровинка: каркас MVP

Рабочая версия по прототипу `../krovinka-prototype.html`. TypeScript везде:

| Папка | Что это |
|---|---|
| `packages/core` | Общие правила без зависимостей: допуск донора, совместимость групп крови, уровни и награды, симптом-чекер (`RED`), валидация SOS, тихие часы. Используются и сервером, и интерфейсом, поэтому проверки совпадают |
| `apps/api` | API на Fastify + PostgreSQL/PostGIS: вход, питомцы и медкарта, SOS, подбор доноров по радиусу, рассылка волнами, отклики, поездка донора, подтверждение сдачи, чат, капли |
| `apps/web` | PWA на Next.js: экраны из прототипа |

## Запуск

Нужны Node.js 22+ и PostgreSQL 15+ с расширением PostGIS.

```bash
docker compose up -d                 # PostgreSQL + PostGIS на localhost:5432 (или свой сервер)
npm install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local
npm run seed                         # миграции и справочник клиник
npm run dev:api                      # http://localhost:4000
npm run dev:web                      # http://localhost:3000
```

Вход по телефону в разработке: код из СМС пишется в лог API (`SMS_PROVIDER=log`). В продакшене этот режим запрещён.

Проверки:

```bash
npm run typecheck
npm test     # тесты core и интеграционные тесты API на базе krovinka_test (TEST_DATABASE_URL)
```

## Как устроено

**Подбор доноров** (`apps/api/src/services/matching.ts`). SQL отбирает кандидатов по виду, группе, весу, возрасту, интервалу после сдачи и радиусу от клиники (`ST_DWithin`). Затем каждый проходит `eligibility()` из `core`: те же правила, что пользователь видит в анкете. Рассылка идёт волнами 10 → 20 → 40 км. Следующая волна запускается, если донора не выбрали за 10 минут (срочно), 30 минут (сегодня) или 2 часа (плановая), а также сразу после «Донор не приедет». Ночью SOS получают только те, кто включил «Будить ночью». Сообщения отправляются после COMMIT, чтобы медленный Telegram не держал блокировку.

**Приватность.** Точный адрес не хранится: точка питомца — центр района со сдвигом. Телефон донора видит только хозяин и только после выбора. Публичная страница `/r/<slug>` без личных данных. Есть выгрузка и удаление своих данных.

**Капли** считаются только на сервере, журнал `xp_events` с `UNIQUE (user_id, kind, ref)`: одно событие начисляется один раз. За сдачу — только после подтверждения хозяином («Кровь взяли»). Сдача вне Кровинки сразу сдвигает дату готовности, но капли ждут подтверждения клиникой.

**Безопасность.** Сессия в httpOnly-cookie, в базе только хеш токена. Изменяющие запросы принимаются только с `Content-Type: application/json` (вместе с `SameSite=Lax` это защита от CSRF). Лимиты: 5 СМС в час с IP, повторная отправка через 60 с, 5 попыток кода, 3 SOS в час на пользователя. Адрес возврата после входа проверяется `safeReturnTo()`. Подпись Telegram Login Widget проверяется по документации Telegram.

## Отличия от прототипа

- Проверка прививок строже: нужны обе (комплексная и от бешенства) не старше года. В прототипе при пустой медкарте проверка проходила.
- «Яд» в тревожных признаках ловится как отдельное слово. В прототипе `\bяд` не срабатывал на кириллице.
- Аккаунты разных способов входа не склеиваются автоматически по телефону: привязка — только из настроек, когда пользователь уже вошёл. Исключение — вход по коду из СМС: кто подтвердил номер, тот и владелец аккаунта с этим номером.

## Что ещё не сделано

- **СМС-провайдер.** Нужна реализация `SmsSender` (SMS.ru, SMSC, МТС Exolve).
- **Telegram-бот.** Сейчас бот только отправляет SOS со ссылкой на запрос. Кнопки «Могу приехать / Не сейчас» прямо в сообщении требуют обработчика `callback_query` — отдельный сервис.
- **Web Push.** Обработчик в `public/sw.js` есть, нужны VAPID-ключи, хранение подписок и отправка с сервера.
- **ИИ** (YandexGPT или GigaChat через свой прокси): уточняющие вопросы симптом-чекера, «SOS одной фразой», распознавание ветпаспорта. Сейчас работает запасной вариант на правилах; промпты лежат в прототипе.
- **Фото** питомцев и документов: объектное хранилище, сжатие, удаление EXIF.
- **VK ID, Сбер ID, МТС ID.** Таблица `auth_identities` их уже допускает.
- **Истории спасения**, рейтинг районов, задания недели, учёт репостов и приглашений.
- **Реалтайм.** Карточка запроса обновляется раз в 10 секунд; потом — WebSocket или SSE.
- **Кабинет клиники** для подтверждения сдачи вне Кровинки.
- **Тексты** политики конфиденциальности и согласия на обработку ПД (`/privacy` — заглушка), уведомление Роскомнадзора.
- **IP для лимитов.** API доверяет `X-Forwarded-For` (`trustProxy`). В продакшене API должен быть доступен только через свой прокси (nginx), который перезаписывает этот заголовок, иначе лимит СМС по IP можно обойти.
- **Клиники** в `seed.ts` — из прототипа, координаты по центру района, телефоны-заглушки.
