# Кровинка: передача прототипа в разработку

«Кровинка» — PWA для поиска доноров крови для собак и кошек в Санкт-Петербурге. Хозяин, которому срочно нужна кровь, создаёт SOS-запрос. Подходящие доноры рядом с клиникой получают уведомление и откликаются. Хозяин выбирает донора, и оба едут в клинику. Кровь берёт ветеринар. В MVP клиника не пользуется приложением, это просто точка на карте.

## Что в архиве

| Файл | Что это |
|---|---|
| `krovinka-prototype.html` | Кликабельный прототип. Один файл, открывается в любом браузере двойным щелчком, без сборки и установки |
| `yandex-id-auth.js` | Пример серверной части входа через Яндекс ID (Node.js, Express) |
| `README.md` | Этот документ |

## Как смотреть прототип

Откройте `krovinka-prototype.html` в браузере. Удобнее всего в режиме телефона: DevTools → Device toolbar, ширина 390 px.

Демо-входы:
- **Telegram или Яндекс ID** — готовый аккаунт «Анна» с питомцем Джесси, уровнем и наградами.
- **По телефону**, код `1234` — новый пустой аккаунт, после входа появится онбординг «Есть собака или кошка?».

В профиле внизу есть блок **«Демо: ошибки»**. Там можно включить отсутствие интернета, пустую ленту и сбой сервера при отправке SOS, а также открыть уже закрытый запрос.

## Прототип — это образец, а не код для продакшена

Всё хранится в памяти браузера и пропадает при перезагрузке. Сервера нет. Рабочую версию нужно писать заново, взяв прототип за образец экранов, текстов и бизнес-логики.

### Что имитируется и что нужно сделать по-настоящему

| В прототипе | В рабочей версии |
|---|---|
| Доноры, клиники, запросы, истории: захардкоженные демо-данные (`DONORS`, `CLINICS`, `state.requests`) | База данных, CRUD, модерация |
| Отклики доноров приходят по таймеру (`dispatch`) | Рассылка SOS подходящим донорам через Telegram-бота и Web Push, реальные отклики |
| Вход через Telegram, Яндекс ID, СМС имитируется (`finishLogin`, код `1234`) | Telegram Login, Яндекс ID OAuth (пример в `yandex-id-auth.js`), СМС-провайдер с лимитами попыток |
| Капли, награды, рейтинг считаются на клиенте | Считать на сервере, иначе их легко накрутить. Сдачу крови подтверждает клиника или хозяин, которому помогли |
| ИИ-функции ходят в Claude через среду просмотра прототипа (`askJSON`) | Свой бэкенд-прокси к YandexGPT или GigaChat (152-ФЗ). Промпты можно перенести почти без изменений |
| Геолокация: координаты районов (`DIST_C`) и расчёт расстояний на клиенте | PostGIS, поиск доноров по радиусу на сервере. Точные координаты пользователя никому не показывать, только район |
| Фото хранятся как data URL в памяти | Загрузка в объектное хранилище, сжатие, удаление метаданных (EXIF с геотегами) |
| Ссылки `krovinka.pet/r/...` — заглушки | Публичная страница запроса, доступная без входа, с кнопкой «Откликнуться» |

## Где в прототипе лежит логика

Весь код внутри одного `<script>` в конце файла. Искать удобно по имени функции.

**Правила и данные, которые стоит перенести как есть:**
- `eligibility(pet)` — допуск донора: возраст 1–8 лет; вес собаки от 25 кг, кошки от 4 кг; действующие прививки; нет хронических болезней; кошка не гуляет на улице; интервал после сдачи 60 дней для собак и 90 для кошек.
- `groupOk()` и `matchDonors()` — совместимость групп крови. Кошкам только та же группа (A, B, AB). Собаке DEA 1.1− только от DEA 1.1−, собаке DEA 1.1+ подходят все. При неизвестной группе подходят все, окончательно проверяет клиника.
- `LEVELS`, `EARN`, `BADGES`, `CHALLENGES` — уровни, начисление капель, награды, задания недели.
- `GUIDES` — тексты первой помощи.
- `reminders()` — напоминания медкарты и готовности к сдаче.

**ИИ (промпты и защитные правила):**
- `RED` — тревожные признаки для симптом-чекера. Проверяются регулярными выражениями **до** вызова ИИ и сразу дают вердикт «срочно». Это важная защита, её нужно сохранить.
- `qPrompt`, `finalPrompt`, `cleanResult`, `ruleResult` — уточняющие вопросы, итоговый вердикт, валидация ответа модели и запасной вариант на правилах, если ИИ недоступен.
- `fillPrompt`, `parseFill`, `normFill` — «SOS одной фразой»: разбор текста в поля формы и текст для районных чатов.
- `SCAN_PROMPT`, `scanDates` — распознавание ветпаспорта по фото.
- `storyAI` — черновик истории спасения.

Каждая ИИ-функция устроена одинаково: промпт, затем JSON-ответ, затем валидация полей, а при ошибке запасной вариант без ИИ.

**Экраны:** функции `view*` — `viewHome`, `viewSos`, `viewRequest`, `viewRequests`, `viewAid`, `viewCheck`, `viewProfile`, `viewAddDonor`, `viewLogin`, `viewNotif`, `viewStories`, `viewStoryNew`, `viewCity` и другие.

**Ошибки и крайние состояния:** `fErr` (ошибка у поля), `offlineBanner` и `flushQueue` (SOS в очереди без сети), `viewSosError`, `emptyReqs`, `stateCard`. Лимит попыток кода из СМС и таймер повторной отправки — в `bindForms` и `viewLogin`.

**Дизайн:** цветовые токены светлой и тёмной темы — CSS-переменные в начале `<style>`. Шрифты Onest и IBM Plex Mono из Google Fonts, лицензия OFL. Для продакшена в РФ шрифты лучше раздавать со своего сервера, а не с Google.

## Путь после выбора донора, подтверждение сдачи, настройки

- **Хозяин** после выбора донора видит карточку «Донор едет к вам»: шаги Выбран → Выехал → В пути → На месте → Кровь взяли, примерное время, чат и телефон. «Донор не приедет» снимает донора и сразу запускает следующую волну. На шаге «На месте» появляется «Кровь взяли, подтвердить сдачу», после чего запрос закрывается и открывается форма истории. В прототипе статусы донора идут по таймеру (`tripSim`).
- **Донор** после отклика ждёт выбора. Когда его выбрали, видит адрес клиники, кнопки «Я выехал(а)» и «Я на месте», чат, маршрут и «Не смогу приехать». Можно отменить отклик до выбора. Сдача засчитывается только после подтверждения хозяина (в прототипе через 5 секунд, `pickedSim`).
- **Подтверждение сдачи.** Донор больше не может сам отметить сдачу и получить капли. Сдачу вне Кровинки он отправляет на подтверждение клинике: дата учитывается сразу, чтобы не присылать SOS раньше срока, а капли начисляются после подтверждения (`creditDonation`).
- **Чат** привязан к запросу (`r.msgs`): системные события статусов, сообщения, быстрые ответы. В рабочей версии нужны доставка через бота и push, модерация и хранение по 152-ФЗ.
- **Главная** показывает плашку «Активный SOS», пока идёт поездка.
- **Настройки** (шестерёнка в профиле, `viewSettings`):
  - уведомления о SOS: вкл/выкл, «Будить ночью» (по умолчанию выключено), тихие часы, радиус первой волны 5, 10 или 20 км;
  - каналы: Telegram и push; предупреждение, если выключены оба;
  - другие уведомления;
  - способы входа: привязать или отвязать, последний отвязать нельзя;
  - приватность: фото питомца и имя в откликах;
  - данные: запросить свои данные, выйти, удалить аккаунт с подтверждением.

## Модель данных (черновик)

- **User**: id, имя, телефон, провайдеры входа (telegram_id, yandex_id), район, настройки уведомлений, капли, согласие на обработку ПД с датой.
- **Pet**: id, владелец, вид (dog, cat), кличка, порода, дата рождения, вес, группа крови, район, фото, «гуляет на улице» (для кошек), хронические болезни, флаг «получать SOS».
- **MedRecord**: питомец, тип (комплексная прививка, бешенство, клещи, глисты, анализ), дата, фото документа.
- **Donation**: питомец, клиника, дата, запрос, кем подтверждена.
- **Clinic**: название, адрес, координаты, круглосуточная или нет, есть ли банк крови, телефон.
- **Request (SOS)**: автор, вид, вес, группа, клиника, срочность (now, today, plan), причина, статус (open, donor_chosen, closed), публичный slug, текст для чатов.
- **Response**: запрос, питомец-донор, статус (offered, chosen, declined).
- **Story**: автор, спасённый, донор, текст, фото, статус модерации, благодарности.
- **XpEvent / Badge**: журнал начислений капель и полученные награды. Всё считается на сервере.

## Ключевые сценарии для MVP

1. **SOS:** форма или одна фраза → подбор доноров (вид, вес, группа, радиус 10 км, готовность) → рассылка в Telegram и push → отклики → выбор донора → обмен телефонами → закрытие запроса → история.
2. **Регистрация донора:** питомец → живая проверка требований → попадание в базу доноров → напоминания о готовности к сдаче.
3. **Медкарта и напоминания** через Telegram-бота.
4. **Симптом-чекер** с правилами до ИИ, раздел «Экстренно» с круглосуточными клиниками.
5. **Вход:** Telegram, Яндекс ID, VK ID, Сбер ID, МТС ID, телефон с кодом.

Позже, после MVP: кабинет клиники, партнёрские награды за капли, потеряшки, прогноз нехватки крови.

## Инфраструктура и требования

- **152-ФЗ:** персональные данные хранятся на серверах в РФ (Yandex Cloud, Selectel, VK Cloud). Нужны согласие на обработку, политика конфиденциальности и уведомление Роскомнадзора. Телефоны доноров показываются только выбранному хозяину и только после выбора.
- **Уведомления:** Telegram-бот как основной канал. Web Push на iOS работает, только если PWA добавлено на экран «Домой», поэтому при регистрации донора нужна подсказка.
- **Предлагаемый стек:** PWA на React или Next.js; бэкенд на Node.js или Python; PostgreSQL с PostGIS; отдельный сервис Telegram-бота; объектное хранилище для фото; очередь для рассылок.
- **Безопасность:** лимиты на создание SOS и попытки СМС-кода, модерация историй и отсев фейковых запросов, подтверждение сдачи крови для начисления капель.

## Вход через VK ID, Сбер ID, МТС ID

На экране входа: Telegram (основная кнопка), затем Яндекс ID, VK ID, Сбер ID, МТС ID и вход по телефону. Во всех случаях ключ пользователя — стабильный идентификатор провайдера (`sub` или `id`). Один пользователь Кровинки может привязать несколько провайдеров: связываем их по подтверждённому телефону, после явного согласия пользователя.

- **VK ID.** Приложение создаётся в кабинете VK ID для бизнеса (id.vk.ru/business). OAuth 2.1 с PKCE. Есть Web SDK `@vkid/sdk` с готовыми виджетами: OneTap, FloatingOneTap, OAuthList (VK, Mail.ru, Одноклассники). Код меняем на токен на бэкенде. Права: `phone`, `email` по необходимости.
- **Сбер ID.** Нужно юрлицо: регистрация организации на портале Сбер ID, подписание оферты через ЭДО, выдача Client ID, Client Secret и сертификата безопасности. OAuth2/OIDC, данные пользователя через userinfo (идентификатор — `sub`). Есть JS SDK. Важно: вход по Сбер ID нельзя встроить в iframe, только переход или всплывающее окно. Сроки подключения закладывать с запасом из-за документов.
- **МТС ID.** Подключение через заявку на business.mts.ru, согласование схемы с менеджером, договор. По данным МТС, базовое подключение бесплатное, платные опции — автозаполнение данных и верификация. Техническая документация выдаётся после заявки.

Порядок внедрения: Telegram → Яндекс ID → VK ID (быстро, без договоров) → Сбер ID и МТС ID (нужны юрлицо и договоры).

## Уведомления о SOS

Решение: **без СМС.** Каналы: Telegram-бот (основной, кнопки «Могу приехать» и «Не сейчас» прямо в сообщении) и Web Push (дублирующий). При регистрации донора подключение Telegram — обязательный шаг. Донор без Telegram и push попадает в базу с пометкой «может не получить SOS вовремя».

Рассылка волнами: сначала ближайшие подходящие доноры, затем радиус расширяется, если донора не выбрали. Точные параметры (стартовый радиус, ночные SOS, лимиты в день) пока в обсуждении.

## Вход через Яндекс ID

Пример — `yandex-id-auth.js`. Схема: `oauth.yandex.ru/authorize` → callback с проверкой `state` → `POST oauth.yandex.ru/token` → `GET login.yandex.ru/info` с заголовком `Authorization: OAuth <токен>` → поиск или создание пользователя по `id` из Яндекса → своя сессия. Приложение регистрируется на oauth.yandex.ru. Права: имя, аватар, телефон. Секрет приложения хранится только на сервере.

Документация: https://yandex.ru/dev/id/doc/ru/how-to
